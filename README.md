# WDTT Panel

Панель в стиле 3x-ui для совместного развёртывания VPN, DNS-туннелей и OpenFlux на одном VPS. Общие пользователи, подписки и маршрутизация Xray. Две темы из палитры RawlineMobile: **OLED** и **белая**.

## Быстрый старт

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/ttrroyy/wdtt-panel/main/install.sh)
```

Установщик запускается от **root** на **Debian / Ubuntu**, архитектура **amd64 / arm64**. Все поддерживаемые ядра устанавливаются сразу. Установщик спрашивает, какие инбаунды создать и включить. Можно выбрать номера или имена через запятую; `all` — все. Первая установка собирает закреплённые версии из исходников и требует времени, памяти и свободного места.

Выберите доступ: **HTTPS через Nginx** (по умолчанию), **HTTPS через Caddy** либо **только локально**. Публичный режим использует домен и **443 одновременно для панели и подписок**; сертификат выпускает и продлевает Certbot через HTTP-01 на 80. Перед установкой проверяются совместимость выбранного режима, занятые порты, подсети и действующий прокси. Чужие службы автоматически не отключаются.

Внутренний сервер всегда слушает **`127.0.0.1`**, на свободном TCP-порту начиная с 2860. Для панели и подписок генерируются **разные случайные пути длиной 17–24 символа**, только латинские буквы и цифры. Установщик печатает адрес; при переустановке пути сохраняются.

После установки выполните на своём компьютере команду SSH-туннеля, которую напечатает установщик:

```bash
ssh -L 2860:127.0.0.1:2860 root@VPS_IP
```

В локальном режиме откройте напечатанный адрес через SSH-туннель. Домен не требуется; конфиги копируются вручную, автоматическая подписка снаружи недоступна. Логин и случайный пароль лежат на VPS в `/etc/wdtt/install-credentials`, доступны только root.

Отдельные режимы CLI: добавьте `panel` (только панель), `node` (только нода) или `combined` (панель с нодой, по умолчанию) к команде установки. Во вкладке **«Ноды»** можно установить только ноду на другой VPS по SSH либо привязать готовую ноду по SSH/HTTPS API-ключу. Веб-панель на ноде не создаётся. Ключ для подключения по API: `wdtt-node-key` на ноде; её HTTPS настраивается установщиком. Вкладка **«API-ключи»** основной панели управляет программным доступом к API с правами чтения или управления.

**Статус текущего обновления:** опубликована промежуточная версия; интеграционные проверки установщика и управления нодами продолжаются. Отдельный конструктор каскадов не входит в панель.

Повторный запуск обновляет панель и все ядра, добавляет выбранные инбаунды и сохраняет пользователей, настройки и ключи. Снятие протокола с выбора установщика не удаляет существующий инбаунд: для этого есть действие в панели. Полное удаление вместе с данными:

```bash
wdtt-panel-uninstall
# либо
bash <(curl -fsSL https://raw.githubusercontent.com/ttrroyy/wdtt-panel/main/install.sh) uninstall
```

Для выбора первоначальных инбаундов без интерактивного запроса задайте `WDTT_PROTOCOLS=wdtt,dnstt,soar,openflux`; для DNS — `WDTT_DNS_ZONE` и `WDTT_DNS_NS`. Пустая DNS-зона означает отсутствие первоначальных DNS-инбаундов; их можно добавить из панели позже. Кнопка «Добавить инбаунд» использует готовые ядра, без фоновой сборки.

Неинтерактивный доступ: `WDTT_FRONTEND=nginx` или `caddy` вместе с `WDTT_DOMAIN=panel.example.org`; необязательный email — `WDTT_CERT_EMAIL`. Для локальной установки: `WDTT_FRONTEND=local`.

## Протоколы

| Протокол | Публичный транспорт по умолчанию | Изоляция |
|----------|---------------------------------|----------|
| WDTT | UDP 56000; WG 56001; RAW 56003 | `10.66.0.0/16`; RAW `10.70.0.0/16` |
| qWDTT | UDP 56100; Direct 56102; RAW 56103 | `10.67.0.0/16`; RAW `10.73.0.0/16` |
| WDTT Plus | UDP 56200 | `10.68.0.0/16` |
| CSQTT 2.1.9 | UDP 56300 | `10.69.0.0/16` |
| CSQTT 2.5.0 | UDP 56400 | `10.71.0.0/16` |
| FreeTurn | UDP 56500 | `10.72.0.0/16` |
| CSQTT 2.5.3 (community) | UDP 56700 | `10.74.0.0/24`, оригинальный релиз Afteroid |
| DNSTT | DNS UDP/TCP 53 | Оригинальный DNSTT, персональная зона и Noise-ключ |
| VayDNS | DNS UDP/TCP 53 | Оригинальный сервер, тип записи и compatibility mode |
| Slipstream | DNS UDP/TCP 53 | Оригинальный QUIC-over-DNS, персональный сервер |
| MasterDNS / StormDNS | DNS UDP/TCP 53 | Один оригинальный движок, персональный ключ |
| CottenDNS | DNS UDP/TCP 53 | Оригинальный движок и персональный ключ |
| Soar | DNS UDP/TCP 53 | Оригинальный SDK; его Dial направляется в Xray |
| OpenFlux | TCP, свободные порты начиная с 56600 | Оригинальный Direct, согласование сессии, персональные секрет и namespace |

Первые семь протоколов создаются по одному экземпляру каждого типа. DNS и OpenFlux допускают несколько инбаундов. DNS-туннели используют общий авторитетный DNS-вход с разделением по именам, а не конкурируют за порт 53. Это все шесть DNS-семейств, которые поддерживает RawlineMobile; StormDNS — имя совместимого MasterDNS-профиля.

Серверы используют исходные реализации. Ссылки сохраняют форматы проектов: `wdtt://`, `qwdtt://`, `csqtt://`, `freeturn://`; DNS-конфиги — `dnst://` в формате, который читает RawlineMobile. OpenFlux Direct выдаёт `openflux://v1/` через оригинальную функцию `--make-link`. Облачные транспорты OpenFlux с учётными записями и URL сторонних сервисов автоматически не создаются.

## DNS-зона

Нужен домен с доступом к DNS-записям. Например, если сервер `203.0.113.2`:

| Тип | Имя | Значение |
|-----|-----|----------|
| A | `ns.example.org` | `203.0.113.2`, **DNS only**, без CDN |
| NS | `t.example.org` | `ns.example.org` |

В установщике укажите зону `t.example.org`, NS-имя `ns.example.org`. Записи AAAA нужны только при реально настроенном IPv6. Не добавляйте A/CNAME поверх делегированной зоны. UDP и TCP 53 должны быть доступны у провайдера VPS. Общий DNS-вход отвечает только за настроенные зоны, рекурсивным резолвером не является.

Панель создаёт отдельные поддомены и ключи пользователей: это позволяет отзывать доступ и применять персональные маршруты даже у движков без собственной базы пользователей. Для Soar базовая зона ограничена 26 символами, для Slipstream — 18: длинные имена мешают QUIC handshake оригинального движка. CottenDNS получает параметры MTU, подходящие для персонального поддомена и AES-GCM. Закреплённые адреса, зоны экземпляров и служебные upstream-параметры в UI доступны только для чтения.

## Пользователи и подписки

Пользователи управляются в отдельном разделе **Пользователи**. При первой установке создаётся главный **ADMIN** с выбранными и созданными инбаундами; удалить его нельзя. На вкладке **Основное** выбираются инбаунды, на вкладке **Подключение** сначала показана подписка, затем конфиги. Для каждой ссылки доступны копирование и отдельный QR с копированием PNG.

У каждого пользователя одна подписка. Из неё можно убрать любой инбаунд и вернуть позднее. Срок **0 дней** и квота **0 трафика** означают безлимит. Общая квота учитывает трафик всех привязанных протоколов; её проверка выполняется раз в несколько секунд, поэтому возможен небольшой перерасход до отключения.

В разделе **Подключения** остаётся таблица инбаундов с портами, подсетью/зоной, состоянием и настройками. Любой поддерживаемый протокол можно добавить сразу: все ядра уже установлены. Персональные DNS-ключи и OpenFlux-секреты хранятся на VPS, не передаются внешнему сервису управления.

## Маршрутизация Xray

**Настройки Xray → Правила:**

| Задача | Поле правила |
|--------|--------------|
| Направить весь инбаунд | **Inbound Tags** → `vpn-<ID инбаунда>` |
| Направить пользователя со всеми выбранными протоколами | **Пользователь VPN** → единый пользователь (`vpn-user-<sub_id>`) |
| Выбрать выход | **Outbound Tag** → существующий outbound |

Пользовательское правило ставится выше общего. Для DNS создаются персональные локальные SOCKS-входы Xray, OpenFlux работает в отдельном network namespace с прозрачным входом. Логическая таблица не требует ручного ввода IP пользователей или подсетей. Входы `vpn-*` управляются контроллером. Доступ из туннелей к локальным контрольным API и частным адресам блокируется.

## Компоненты и проверки

| Компонент | Назначение |
|-----------|------------|
| `wdtt.service` | Локальная панель и обычный WDTT |
| `wdtt-protocol@<тип>.service` | qWDTT / Plus / CSQTT / FreeTurn |
| `wdtt-edge@<экземпляр>.service` | Оригинальный DNS/OpenFlux-сервер отдельного пользователя |
| `wdtt-dns.service` | Общий авторитетный DNS-вход UDP/TCP 53 |
| `wdtt-protocol-watch.service` | Подписки, квоты, Xray-входы и маршрутизация |
| `wdtt-xray.service` | Выход TCP/UDP через выбранный outbound |

Основная БД — `/etc/wdtt/panel.db`. Настройки и ключи — `/etc/wdtt/protocols/`; каталог дополнительных экземпляров — `catalog.json`. DNS-маршруты — `/etc/wdtt/dns-router.json`, Xray — `/etc/wdtt-xray/config.json`.

```bash
systemctl status wdtt wdtt-xray wdtt-protocol-watch wdtt-dns
journalctl -u wdtt-protocol-watch -n 100 --no-pager
# Проверки выполняются на Linux:
python3 scripts/test_protocols.py
python3 scripts/test_edges.py
python3 scripts/test_installation.py
go test ./pkg/... ./panel/... ./server/...
```

Версии закреплены в [scripts/protocol-sources.json](scripts/protocol-sources.json) и [scripts/edge-sources.json](scripts/edge-sources.json). Лицензии и сведения об исходниках сохраняются в `/usr/local/lib/wdtt/protocols/licenses/`.
